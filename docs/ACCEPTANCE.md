# 文字与公式转换验收

## “1:1”的记录方式

文字转换的长期目标是匹配固定 ManimGL 参考的视觉与时间行为。每个通过结论必须指定参考版本、字体、输入、动画参数、分辨率、采样时刻和设备环境；不扩张成所有输入或跨设备逐像素一致。

区分三个层次：

1. **语义一致**：字符/片段匹配、轮廓对应、路径与缓动和参考相同。
2. **数值一致或有界误差**：几何、时间、资源编码与插值误差有实际记录。
3. **实机画面一致**：MC 实际帧与参考帧按同一坐标和颜色条件对照。若使用容差，必须写明；仅近似通过不得描述为逐像素完全相等。

当前未完成上述全部验证的样例保持“待验证”。记录中不能只写“肉眼看起来正确”或“shader 编译通过”。

## 首批样例

| 编号 | 内容 | 主要检查 |
| --- | --- | --- |
| T01 | 静态字形与符号 | 尺寸、基线、填充、轮廓方向和孔洞 |
| T02 | 指定字形连续变换 | 起终点，以及 0.25 / 0.5 / 0.75 进度的真实中间形状 |
| T03 | 相同字符换位置 | 原版匹配结果、重复字符选择、位移路径 |
| T04 | 字符增删 | 原版未匹配部分的行为、透明度和对象生命周期 |
| T05 | 孔洞/轮廓数量变化 | 退化、出现、消失、中间自交和填充 |
| T06 | 公式片段转换 | 排版来源、片段分组、公式基线、括号/上下标 |
| T07 | 中文代表字 | 多轮廓、字体覆盖、复杂度与构建体积 |
| T08 | 播放状态 | 暂停、指定进度、重复播放、关闭与重开 |
| T09 | UI 集成 | 视口缩放、裁剪、遮挡、多实例独立状态 |

首版实际实现的样例由运行报告列出，其余保持待办。T06 需要真实公式排版参考，普通文本的 `a+b=c` 不足以证明复杂 LaTeX 支持。

## 验证方法

- 编译器验证输入边界、数据版本、端点、轮廓信息和重建误差。
- 对同一参考动画独立采样，检查生成结果；不可只拿编译器自己生成的“预期值”互相比较。
- 游戏内设置指定进度并等待真正呈现后截图；同时保存读取到的播放参数与采样时间。
- 数值状态、UI 属性树和实际像素分别记录；窗口截图中的最终颜色与纹理原始字节也分别记录。
- 对齐参考坐标后记录像素差、轮廓偏差与失败区域。差异度量和容差先声明，再解释结果。
- 记录 CPU 构建耗时、资源体积、游戏控制开销与实际帧表现；截图工具耗时不等于 GPU 渲染时间。
- 游戏实例必须属于本项目。手机支持必须有对应设备验证，PC/F11 结果不得替代。
- 所有代理测试保持后台静默、上限 60 FPS。模拟组件回调或键盘事件只验证相应业务路径；真实鼠标命中和硬件按键保留人工复核，不能为补齐记录而激活游戏。

## 证据保存

`.runtime/` 保存完整图片、日志、临时环境和实例回执；小型结果摘要可以进入 `docs/evidence/`。摘要应含运行方式、场景/资源哈希、环境、通过与失败项及已知限制。包含本机 session token 的文件不提交。
