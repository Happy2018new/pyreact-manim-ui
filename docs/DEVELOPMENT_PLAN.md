# 开发路线

## 优先级与交付范围

当前用户优先级是**尽快交付可用版本**：文字转换先行，配合可展示的二维 Manim 风格动画。2026-11-10 用户确认当前轮廓重合率已足够，要求停止继续研究像素差异；严格 1:1 暂不作为交付门槛，也不标记为已完成。本轮优先中文、宋体、系统字体选择和真实 LaTeX，不扩展 3D。

0.2.0 已交付的实现采用宿主 Python 离线执行受支持的场景定义、导出几何与时间数据、生成 shader 的路线。游戏只运行播放器，玩家端无需安装桌面 Manim。

2026-11-10 路线：**保留静态构建作为交付基础，先验证运行时数据入口，再逐步增加运行时场景编排与交互。当前不整体重写为严格 all in runtime。** 字体、复杂排版和参考生成继续使用离线工具；本轮实施结果列在下节，后文保留阶段划分与 A/B/C 判定标准。

## 0.3.0 本轮执行结果

用户已授权执行上述阶段。本轮完成可复用播放状态机、两槽位 Pyreact 独立画布和实时参数图元，按 **B 分支**交付。文字、中文及复杂 LaTeX 继续使用静态构建，业务可在运行时控制场景、时间、布局、透明与图元参数。

动态纹理实验已用游戏 Python 生成的 128 点／256 个数值验证：预置文件路径首次读取准确；覆盖后不会自动刷新；全 shader 重载不刷新；全材质重载后第二组数据准确，但调用长时间阻塞且新增文件路径仍不被发现。它是 C 分支的开发态证据，不满足产品 A 分支。没有用未证明的上传路线继续扩建运行时字体／TeX 解析器。

独立 UI 实测透明、矩形裁剪、前景遮挡、缩放和实例隔离；公开 API 按 identifier 共享参数，因此版本明确限制两个同时挂载的画布。详细结果见 [0.3.0 验收](RUNTIME_ACCEPTANCE.md)，业务接入见 [播放 API](PLAYBACK_API.md) 与 [画布 API](CANVAS_API.md)。

当前下一步按此顺序继续：先人工体验双画布页面和触控／窗口尺寸；修复确认的问题，再提供有限字库数字／标签组合；复杂公式继续编译。若继续追求任意新文本 runtime，需先独立解决发布可用的数据更新入口与容量，不能以本版图元参数能力代替该门槛。每次重新构建静态例后同步生成 UI 资源，阶段末整理接口并保留回归，不扩大 3D 或任意脚本兼容。

## 2026-11-11：资源包图片着色器扩展

按用户新增需求完成独立 `ShaderImage` 组件和“图片变形”演示页。静态PNG先构建到共享图集，游戏运行时控制宽高拉伸、旋转、镜像、裁剪、透明度、波纹和旋涡。采用独立四槽位，不占用原有两个ManimCanvas槽位；静态图片不逐帧提交参数，动画只上传变化的时间组。

已完成90项相关离线检查及后台实机的图片对照、组合变形、暂停、1280×720缩放和页面重开检查，详见 [实现与验证](SHADER_IMAGE.md)。下一步由用户体验图片演示页，再按实际素材或业务场景扩展；第一版未包含运行时下载新图、语义图片变形、任意网格折叠或完整HTML／Flutter引擎。图片滚动跟随、复杂父级裁剪及手机输入仍需专项验证，不从已有画布验收直接推定通过。

## 静态与运行时的职责

| 部分 | 下一阶段推荐安排 | 理由与边界 |
| --- | --- | --- |
| 字体、字形轮廓和数学符号资源 | 优先在构建端准备，可复用与缓存 | 不预制所有文字 A→B 的组合；固定字库资源不等于任意系统字体已能在游戏内解析 |
| 复杂 LaTeX 排版与原生参考 | 保留现有离线链路 | 不把完整 TeX、宏包和 ManimPango 移植纳入下一版 |
| 场景对象、布局、参数和时间轴 | 数据通路验证后逐步迁入运行时 | 在输入或对象变化时构建与缓存；播放帧只更新必要状态，不逐帧解析字体 |
| GPU 绘制 | 先验证固定容量的通用 shader；静态 renderer 保留到新路径通过回归 | 通用化可能增加间接读取和循环成本，不能先假定一定更快 |
| Pyreact 业务调用 | 两条路线共用播放和资源生命周期接口 | 场景来源可不同，不让业务页面依赖具体构建方式 |

这里的目标是“新内容在游戏内组合并生成动画”，允许随包预置字体和符号等基础资源。严格从任意原始字体、完整 LaTeX 到任意 Manim 脚本都在游戏内执行，继续作为未承诺的独立研发方向。

## 第一阶段：有上限的技术验证

建议先给予这一阶段 **4 小时有效开发投入上限**。这是探索预算，不是成功工期预测，也不包含一个完整 runtime 引擎的实现。到点必须形成能力结论、证据和下一分支；信息不足记为“未判定”，继续已有静态交付，不无限延长研究。

1. **先验证数据入口。** 游戏 Python 生成至少 128 个二维点或等量数值，超过现有少量 uniform 的容量；让 GPU 实际读到并可视化，再更新同一资源。检查数值精度、采样过滤、缓存失效、释放及更新耗时。不得用开发机预生成的新图片代替游戏生成的数据。
2. **入口通过后再验证通用绘制。** 同一个预置 shader 根据两组不同拓扑的小场景数据绘制；记录 shader 哈希不变，避免把更换专用 shader 当作运行时通用化。先用简单几何，不先建设字体解析器或完整公式系统。
3. **核对发布条件。** 若采用写文件、资源发现或重载方式，分别检查可写位置、资源刷新和打包环境支持。开发态热重载成功、API 返回 True、SDK 文档存在接口，都不足以证明玩家端可用。
4. **单独测性能。** 分开记录首次初始化、单次内容更新、加载后播放、内存占用和重复创建销毁；固定 60 FPS，不以单次帧率读数替代耗时测量。

公开后处理参数文档目前为 `EXTRA_VECTOR1` 至 `EXTRA_VECTOR4`，共四组 vec4；`SetParameter` 要求既有参数长度一致，不能视为任意顶点数组上传。公开 `ReloadOneShader` 等接口存在，但尚未证明新资源写入、纹理更新和发布环境的完整链路。没有查证到通用上传入口，不等于引擎绝对无法实现；这些正是第一阶段需要实测的部分。

| 分支 | 判定条件 | 后续工作 |
| --- | --- | --- |
| A：动态数据入口可用 | 可重复更新，精度/释放/成本合格，发布环境可用，同一 shader 可消费新数据 | 建设固定字体或字库、短文本、基础图形和有限公式语法的运行时构建；先小场景再扩容量 |
| B：只有预置资源与少量参数 | 只能选择已部署的数据、传少量 ID/数值或变换参数 | 做数字、固定长度标签、有限槽位对象和参数化动画；明确字数/对象上限，不称为任意文本生成 |
| C：开发态依赖或成本不可接受 | 只能依赖开发热重载，或资源发现、缓存、延迟使产品不可用 | 继续离线场景编译，改善缓存和增量构建；暂不投入运行时字体/TeX 解析器 |
| 未判定 | 探索预算内不足以确认上述条件 | 保存已有证据和下一验证点，按静态路线继续可交付工作 |

## 下一版的交付顺序

1. **可复用的播放组件。** 业务可以创建、播放、暂停、跳转、切换和销毁场景；资源、错误和页面关闭行为清楚，不依赖演示页面的“上一例/下一例”。
2. **UI 画布验证与接入。** 先约定尺寸、可见性、透明和清理行为，再验证渲染载体；以两个不同区域、部分遮挡、透明背景、裁剪、缩放和反复开关为最小验收。若载体不满足条件，只交付明确标注为全屏后处理的组件，不冒称独立 UI 画布。
3. **首次加载性能。** 为现有中文冷加载建立实际耗时基线，再选择缓存、预热、避免重复安装或 shader 结构调整。任何优化都同时验证首次等待与后续播放；不以增加启动等待掩盖切例等待。
4. **按 A/B/C 分支加入一项实际动态能力。** A 分支先验证未预制的短文本组合和对象变换；B 分支优先数字/固定长度标签或进度等参数化展示；C 分支完善静态场景的业务调用与重新构建流程。
5. **回归与打包。** 保留十例视觉和播放器回归，新增组件生命周期/数据变化用例，继续后台静默、60 FPS 测试。

更自然的字符与公式片段匹配，在基本调用和数据路线稳定后推进。下一版暂不承诺完整 LaTeX runtime、任意系统字体 runtime、任意 Manim 脚本、3D 或手机全面支持。运行时探索与 UI 载体分别存在技术风险，交付说明必须按实际通过的分支填写。

## 实机与性能规则

- 代理测试全部后台静默，使用挂起启动前安装的防激活保护；后台 SDK 状态操作和 WGC 截图不抢焦点。缺少保护时停止，不回退普通启动。见 [后台测试约定](BACKGROUND_TESTING.md)。
- 所有 MC 测试固定 **60 FPS**，不启用无限帧率。`tools/start_dev.py` 在启动前检查 Windows 原生 roaming 下的有效 options；修改前保留独立备份。
- 如果需要修改帧率配置且存在 MC 进程，启动器拒绝改写，不通过关闭其他会话来强行应用。配置已为 60 时不重复改写。
- 0.1.0 的六例测量作为历史记录保留；0.2.0 十例、30 张实机图和逐例播放已完成，见 TEXT_FORMULA_ACCEPTANCE.md。十次短时播放采样约 60.08 FPS，首次中文加载仍有明显等待，不能据此宣称全程无卡顿。
- 新版检查起点、中间态、终点、播放状态、切例、导航关闭和模拟 F8 事件重开，另修复并验证缩放后的物理视口刷新。真实按键交由人工复核，代理不激活游戏。
- CPU 预览、桌面 OpenGL 参考与 MC 截图分别保留。shader 编译成功或接口返回成功不等于画面通过。

## 定期整理与计划更新

每个阶段完成后进行小范围整理：固定 IR 与运行时契约，清理实验入口，减少重复路径，检查依赖归属，重跑关键字形和播放器回归。严格字形路线与预览近似需保留明确边界，不能靠兼容分支掩盖失败。

以实际验收关闭项更新后续估算。本轮没有继承旧投影项目的工期、额度、截止时间或休眠指令；“尽快初版”通过限制范围和优先集成实现，不虚构未经测量的完成日期。
