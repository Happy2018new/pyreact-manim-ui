# Stencil 候选实机复测

这次在网易版 Windows OpenGL 3.10.0.467018 上用相同的 65,536 字节输入，常规视口为 720×1080，帧率上限为 60 FPS。各用例使用独立受管实例、被动 WGC 截图和全量数据读回。帧率上限是测试设置，本轮未采集性能数据。

## 独立粒子和普通特效

两个实际资源包顺序均验证通过。每个顺序中，16 项原生 FrameAni 画面对照通过，60 张数据诊断零错。有 32 张图同时验证序列帧与全量数据。两轮共 218 张截图中的额外包专有图样均准确，实际世界资源包 UUID 顺序确实反转。雨天也通过了完整数据、源符号和实际非 255 alpha 检查。

无额外包的首次画面对照受到镜头扰动。重新运行时相机固定，所有 56 张数据诊断零错，普通序列帧可见。16 项严格视觉检查中有 14 项通过。数据区内两项加法序列帧各有 8 个像素超过原验收公式的 3 级容差，最大差为 4。用相同场景下的原生画面直接比较，这两项的最大通道差均为 2。独立复算确认，先做原生加法混合、再走既有 6 bit 场景恢复的模型与三轮取样的 1,728 个 RGB 像素完全一致。验收公式使用恢复后的底色重新做混合，两个计算顺序会因量化得到不同结果。严格原判定仍保留未通过。

## 阴影

原版阴影读掩码 255 复现 196 个缺失阴影像素，全部对应 bit 64 被写入的位置。掩码 191 和 63 都保留了全部四类符号对应的阴影，受控场景的 20,378 个几何参照像素均在每通道误差 2 以内，完整数据和保护区零错。三组无载荷的画面对照也逐像素完全相等。191 只放宽对 bit 64 的检查，改动范围更小。原生阴影材料与其他效果共存还要单独验证。

## 维度与后处理

最初用原固定相机运行，在下界拿到接口成功回执但 65,280 字节读错，返回主世界后自动恢复。后续将相机和载体移到两维度均有效的正 Y 高度，只准备主世界脚下地形，下界保留自然地形。一次主世界进下界再返回的两张首次被动诊断图中，全部 65,536 字节和保护区精确匹配。后续逐源符号检查也零错。两次恢复复用了原有几何页，原生几何创建次数保持为 3。主世界 990 个测试位置均已恢复。这一轮补测当时覆盖了一次下界往返，连续往返和末地的后续结果见下文。

原生景深首次复测的测试包把自定义材质写入了客户端未注册的文件。将定义合并进已加载的 `postprocess.material` 后，使用原生景深材质名及原生 shader 的参考用例通过。零模糊和恢复零模糊时，参考区 262,144 个 RGB 像素完全匹配。近景、远景和自动对焦的非零参数产生了独立的画面响应。

载荷开启后的零模糊和最后恢复零模糊，数据区与参考的逐通道差均在 2 以内，三种晚期诊断的 64 KiB 数据、恢复画面及诊断保护区均通过。静止场景严格对照仍未通过：两次独立世界单是零模糊就在外圈有 5,579 个差异像素，手动近景、远景、自动对焦在数据区内分别有 15,440、15,244、10,659 个像素超过容差。两次独立世界各自的零模糊与回零帧一致。跨世界的外圈差异全部落在地面，天空对应区域完全相同；有模糊时，数据区内超差像素也集中在地面侧的底部和侧边。现有对照不能分离底图差异与候选着色器差异，景深兼容性仍未关闭。

Bloom 的 T3 跨过程连接在材质注册修正后仍被拒绝。随后使用普通前序纹理的源对照绕开 T3，采集到六张真实截图，但截图依然显示原场景，白块未得到预期 RGB，alpha 也未从 255 切换到 0。源对照未通过，因此有原生 Bloom 的阶段没有启动。本轮对 Bloom 的执行和共存仍无法判定。

## 范围

本轮测试以 64 KiB Windows 实机为限。ADB 未检测到连接的设备，手机仍无实机结果。alpha 打包和 512 KiB 帧时间仍在后续验证范围。

各项状态、独立复算和清理回执见[证据索引](evidence/native-stencil-candidate-retest/summary.json)。


## 掩码 191 同屏与后续验证

- **晴天同屏通过。** 受管 720×1080 测试场景中，跨数据区边界的阴影、实体描边、方块填充高亮及矩形 UI 裁剪同时可见。两张同帧诊断中，分别检查 65,536 字节和 262,144 个源符号，数据和保护区零错。三种对象的全部预声明画面区域没有像素超过每通道误差 2。已按原门槛重跑，遮住了独立场景内自然活动的背景动物并在清理时恢复。
- **雨天通过数据和 UI。** 同一组数据与 UI 零错，源符号截图中有 4,328 个 alpha 非 255 的实测雨天像素。雨在各张参照之间移动，关闭 → 开启 → 关闭的画面稳定性检查未通过，阴影、描边和高亮的严格视觉比较仍未验收。
- **固定景深场景未取得截图。** 两套包已准备。测试在读取环境状态的第一步遇到 Windows 套接字资源不足错误 `WinError 10055`。固定房间、整幅零模糊外围门槛和非零配置的离线检查通过。
- **连续主世界／下界／末地未运行到传送。** 准备并启动了新用例，但系统可用提交内存约 2.46 GiB，低于加载门槛。此前单次下界往返结果仍可复现。新增脚本已准备好依次检查六次切换。
- **Bloom 未判定。** 三张新图源对照显示客户端拒绝编译图源里的 GLSL 保留字。已修正并重新生成两套测试包，原生光晕阶段仍待实际图源阳性之后再测。

同屏实机证据位于本机 `.runtime/native-stencil-combination-20261119-r1/shadow-joint-guard`。固定景深及连续维度的受管启动记录位于该目录树的 `dof-identity`、`dimensions` 两个用例子目录。这些启动记录与后续通过的固定景深和遮雨对照分开保存。


## 固定场景、雨天、维度及 Bloom 补测

- **固定场景景深通过。** 使用同一方块布局、相机和固定天气，有载荷和无载荷的零模糊画面在数据区外 **429,056** 个比较像素完全相等。零模糊、手动近景、手动远景、中心自动对焦和恢复零模糊的原验收区均无像素超过每通道误差 2，最大通道误差分别为 **2／1／1／2／2**。晚期直接读取、依赖读取、画面恢复与诊断保护区均通过。该实验使用固定数据区和固定视口。
- **雨天遮挡区同帧图像在既定容差内。** 玻璃顶棚和背景墙遮住三个效果的验收区域。两张完整数据图相对载荷关闭、全部效果开启的后期原生参考，阴影、描边和高亮各自的完整检查区域均无像素超过每通道误差 2，UI 和完整载荷检查零错。这些图同时保留雨天暴露区，预先指定的 23,040 个暴露区像素中有 602 个 alpha 低于 255，全部源符号仍正确。原组合判定仍为失败，唯一失败的地面控制比较混用了早期原生参考和后期载荷帧，前段已随原生画面变化最多 4，后段恢复变化最多 2，直接叠比造成 273 个像素超过该检查的容差 4。这次结论覆盖遮雨的效果区域。
- **下界和末地都复现自动读回失败。** 下界失败场景的相机、载体和特效周围 59 个采样点都读到下界岩，65,280 字节错误。末地同样范围的 59 个点都读到空气，仍有 65,281 字节错误。各三张后续被动截图观察了约 12 秒，错误数没有下降，两次返回主世界后均完整恢复。下界需要选择避开实心方块的锚点，末地还需要把模板写入、晚期读取、切换后重绑定位到具体一段。
- **Bloom 光源通过，原生光晕仍未证实。** 编译修正后，三张无 Bloom 图和三张启用原生 Bloom 图在固定分析区全部精确显示预期的黑底白块。两组画面逐像素相同，暴露在光源外的光晕像素为 0。新光源对照没有独立采样实际 alpha，当前仍无法确认原生 Bloom 阶段是否执行、该阶段是否收到图源。

这些测试未记录 512 KiB 或正式帧时间。实测状态、独立复算和自有实例关闭验证见[续测证据索引](evidence/native-stencil-continuation/summary.json)。

## 末地 64 KiB 分阶段诊断

同一份 65,536 字节输入只上传一次。主世界首次和返回后的完整读回均为零错，进入末地后的第一张自动读回有 **65,281 字节错误**。末地原地完成了 21 张阶段图、3 张已知色块对照，以及 6 张手动干预后的数据图。测试视口为 720×1080，帧率上限为 60 FPS。

- **后处理复制正常。** 10 张原始 RGB 导出图，每张都把画面中 262,144 个源像素和同一帧的后处理副本同时显示出来。两区域所有通道逐像素相同，保护区零错。
- **失败已经出现在生成数据画面的阶段。** 仅开启基础混色特效时，仍有 7,428 个源像素的绿或蓝超过混色后的上限 63。不使用 stencil 的独立已知色块特效也没有出现在原画面中，262,144 个像素全部与预期不符。该对照把问题缩小到特效绘制或其结果在复制前的保留环节，仍无法单独判断几何体是否写入 stencil。
- **三次重新设置均未恢复。** 依次重连后处理、重新创建三个晚期特效、用原有缓存页重新创建几何载体。每一步均取得回执和后续帧，读回都仍有 65,281 字节错误。返回主世界后两种诊断完整通过，主世界 990 个临时测试位置全部恢复，自有测试实例已关闭。

### 末地特效裁剪对照

独立第二次往返先在主世界验证已知色块，屏幕和后处理副本的 262,144 个像素均精确匹配。末地自动读回再次错 65,281 字节，同一测试色块再次完全缺失。

对同一批特效 ID 调用 `FrameAniControl.SetGlobal(True)` 后，颜色对照两个区域全部匹配，64 KiB 完整字节读回和 262,144 个源符号均零错。相机、中心屏幕射线、玩家位置、几何页和后处理连接维持原状态。该 SDK 设置让序列帧跳过摄像机视野裁剪，单独启用就足以恢复这次末地渲染。这个对照保留了进入末地时的自动失败，后续元数据重设和移动特效没有触发。

### 自动恢复复测

维度切换恢复时，新建的三个传输特效各设置一次 `SetGlobal(True)`，然后再重连后处理并发布就绪。三个调用都必须有成功回执。

- **末地往返通过。** 新实例进入末地和回到主世界后的首次自动捕获均读回完整 65,536 字节，错误为 0。两边的后续完整字节和逐源符号核验也全部通过。全程只上传一次，保留同一批缓存几何页，几何构建次数始终是 3。
- **下界固定机位仍失败。** 三个 `SetGlobal(True)` 均成功，首次自动读回仍有 65,280 字节错误。相机、载体与特效周围采样的 59 个点全部是下界岩。返回主世界后自动和后续核验都零错。下界仍需在无遮挡的落点复测，当前结果只覆盖这个固定机位。

两次复测的主世界临时场地均精确恢复了 990 个位置，受管实例已关闭。截图、读回和清理的文件及哈希见[维度分阶段证据索引](evidence/native-stencil-dimension-stage/summary.json)。
