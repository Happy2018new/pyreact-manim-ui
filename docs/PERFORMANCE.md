# 编译输出与全屏性能

2026-11-10：用户反馈数学 V9／童话 V5 在最大化或全屏窗口中卡顿，随后要求只修改源码与编译器，不启动游戏复测。本轮没有启动 Minecraft。60 FPS 配置只限制帧率，不能证明实际每帧在 16.7 ms 内完成。

## 本轮改变

### 通用 IR 编译器

`src/pyreact_manim/compiler/shader.py` 对 Schema 1 和 Schema 2 独立检查几何、填色、描边色与描边宽度是否在**全部关键帧**保持不变。恒定属性直接读取第一帧的图集数据，省去第二帧读取和插值，继续使用原来的 RG16 解码。首尾相同但中间发生变化的属性仍走动态路径。

Schema 2 新增每条完整曲线扇形的保守边界。边界包含公共基点、所有关键帧的曲线顶点、量化误差、浮点余量、真实边线及抗锯齿范围、四个子像素的偏移。只有完整扇形不可能贡献填充或边线时才跳过。不能只用真实曲线的边界剔除，因为基点到曲线之间的辅助边仍参与有向填充。

已有整路径边界、平衡时间选择、常量活动标记折叠、孔洞抵消和透明 UI 合成均保留。图集布局、场景 Schema 和运行时 uniform 接口兼容，manifest 新增 `shader.generator_revision = 2` 与优化说明。

### 字形／字幕编译

`tools/presentation/vector_morph.py` 在生成整句／整组公式前计算保守屏幕边界。屏幕像素位于边界外时跳过整组字形分支；边界包含源／目标完整 SDF tile、位置与尺寸插值、弧形位移、旋转、生成常量的舍入及浮点余量。超出 `[0,1]` 的进度绕过新剔除，以保留原先外插行为。

字形原有孔洞、轮廓拓扑、每轨最多256个记录、SDF端点和中间形变均保留。常量字形仍使用静态路径，端点仍提前退出轮廓遍历。

### 两部影片的参数几何

数学片把时间缓动、相位、旋转、缩放等移出逐段循环，用平方距离比较最近线段，并把原有曲线划分为4段／8段小组。若每个坐标满足二阶导数界 `|C''| ≤ M`，则组内曲线位于端点盒向外扩展 `M·Δu²/8` 的区域中；先比较盒到像素的距离下界，再决定是否计算原有线段。原来的5×112花瓣、4×112波形、9×64曲面及5×64开场／收尾采样保持不变。

童话片对非旋涡风流的单调三次 x 坐标做二分定位；旋涡风流使用分组曲率边界。花瓣用固定角度递推和倍角恒等式复用采样相位，归位尾迹复用 Bézier 控制点并按轨迹凸包剔除，流星按单调首尾边界剔除。24束花瓣×7丝、3股风流×13丝以及原有32／52／10／28段采样全部保留。

空间剔除只跳过不可能影响像素的工作。数学曲线搜索额外在至少1世界单位处截断极远光晕，该位置原有每条光晕贡献低于 `2e-10`。运算重排存在浮点差异，不能把生成 shader 声称为逐像素完全相同：旧离线对比中，数学自交处出现极少数近似等距线段选择不同颜色的像素，童话全高清采样最大通道差为 `3/255`。

## 验证与资源

最终集成采用源码、单元和 CPU 数值检查；没有游戏复测或新视频导出。检查覆盖内部关键帧变化、独立属性恒定性、完整扇形填充与边线、量化和浮点边界、文字旋转包围盒、时间轴以及两种 Schema 到透明 UI 的转换。最终记录见 `docs/evidence/performance/compiler-v2.json`。

八个文本示例从既有 IR 重编译，两个基础二维示例从 Python 场景重编译，随后重建独立 UI 画布与两部影片资源。10个通用场景的图集哈希全部与原部署一致；仅改绘制计算方式。两部影片的字形图集也保留原始数据。无需重新生成字体／LaTeX参考。

此前独立桌面 GL 的几何部分采样显示，数学花瓣／扭结约24–26 ms降至11–12 ms、曲面约21 ms降至9–10 ms；童话所采样段落降低约17%–71%。这些数据不包含完整 Minecraft 渲染负载，也不能外推为最大化窗口稳定60 FPS。用户要求静态处理后，不再追加帧率或画面复测。

现有 V9／V5 MP4 保留为视觉版本参考；它们的 `.render.json` 对应优化前 shader。当前优化资源的哈希记录在本轮编译证据，不覆盖历史导出记录。

## 后续编译约定

- 编译阶段优先折叠已知不变量，再产生时间选择与空间剔除；不能用首尾相等代替整段恒定。
- 剔除必须有覆盖填充、描边、抗锯齿、量化和时间插值的保守依据；不能按主观可见性删掉曲线或孔洞。
- 重复参数曲线先复用时间不变量和解析关系，再减少无关像素的扫描；保留原始采样集合和动画节奏。
- 保持旧图集和运行时接口兼容，生成元数据说明启用的优化；构建成功、离线 GPU 成本与实际游戏 FPS 分别报告。
