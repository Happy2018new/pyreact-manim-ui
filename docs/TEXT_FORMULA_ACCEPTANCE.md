# 0.2.0 中文、宋体与 LaTeX 验收

记录日：2026-11-10，America/New_York。用户要求快速交付，停止继续追逐微小像素差异；后续针对中文灰色三角区域的原因做了单独诊断。严格 1:1 未标记完成，也不作为本版交付门槛。

## 本版内容

- 新增两组宋体中文：**中文 → 变换、数学 → 中文**。
- 新增真正 LaTeX：**分式 a/b → b/a、上标 x² → 根式 √x**。构建执行原生 `Tex`，不将公式源码当普通文字绘制。
- 构建端按已安装字体名称调用字体，支持 TTF、OTF、TTC、OTC；本机 `宋体` 与 `SimSun` 已验证为同一字体、同一轮廓。修复中文别名被 Pango 回退为 Sans 的问题。
- 默认中文字体为从 Noto Serif SC 派生的可分发宋体子集，35,068 字节。缺字、错误字体名称和超出资源预算明确拒绝；系统字体不随仓库或游戏包复制。
- 修正子像素、有符号透明度与细边的合成顺序；原有 O→B、C→S 改用 Schema 2，保留 8→1、UI→UX 和两个二维例子，共十例。
- 每帧顶点预算提升至 2048，纹理边长上限仍为 2048。两个中文场景含共享基点后为 1546、1706 点。
- 修复窗口尺寸事件早于物理尺寸更新的问题：下一渲染帧读取新尺寸；同步播放/跳转不提前消费该刷新，正常帧不重复查询 SDK。

这是离线构建、游戏播放的方案。构建机器使用所选字体生成轮廓，目标机器无需安装相同字体。游戏内临时输入文字、查询系统字体和即时排版尚未接入。

## 原生参考与灰色三角区域

正式比较使用未修改的 ManimGL Camera，每例五帧，共 40 帧。西文四例前景 IoU 为 **99.175%–99.992%**；分式为 **99.042%–99.394%**，上标/根式为 **99.113%–99.833%**。指标针对所列时刻，不代表所有输入和连续时间严格相同。

中文两例的原版指标分别为 **82.279%–99.531%** 与 **69.066%–99.480%**。最低值出现在“中文”端点，主要白色笔画没有明显缺失；差异主要是原生参考在字形空腔和笔画附近出现灰色三角区域，而当前 shader 将这些空白区域保持为黑色。

针对用户要求进行了六组受控实验，结论为：**原生 FP16 有符号 alpha 混合存在消去误差，Transform 补点增加分段后，残余覆盖被放大。** 独立进程的首次渲染和连续三次渲染都与原版端点逐像素一致，排除了导出顺序和相机残留。

只在实验进程内将原生填充纹理由 FP16 换为 FP32，保持相同几何、原生 shader 和 Camera，灰区即消失；两个问题端点与当前 shader 的 IoU 达到 **99.507%、99.622%**。这两项是**修改上游精度的诊断结果**，原版 40 帧基准仍原样保留。当前 MC 不使用该原生逐三角形 FP16 累积缓冲区，实机未出现对应灰色残影，因此没有向游戏加入这些残影。

诊断工具、同源几何哈希、alpha 残余统计及图像见 [独立精度诊断](evidence/text-formula-v020/fill-precision-diagnosis/README.md)。剩余折线采样、时间插值、原生浮点 marker 窗口等近似继续保留说明，本版不再扩大逐像素研究。

## 已知限制与后续顺序

1. **中文 shader 首次安装明显偏慢。** 两个场景首次选择超过调试 IPC 超时，随后只读状态确认加载成功；复用后可以正常播放。精确冷编译时长本轮未埋点测量，不能由 FPS 反推。大量曲线展开的编译成本是后续性能项。
2. 字体存在、字符覆盖通过，不代表任意长句或任意变换均受支持。当前只支持平面填充法线；宋体 `数学 → 动画` 会明确拒绝，默认改用已验证的 `数学 → 中文`。复杂度超过预算时也拒绝。
3. 当前采用原生普通 `Transform`，并非按数学语义匹配公式片段；中间形状可能压缩、交叠和扭结。公式样例、字体范围之外的输入需另行验证。
4. 独立 UI 画布、裁剪、多实例、手机支持和运行时动态排版仍待实现。当前是为控制面板留出空间的全屏后处理。
